# AGENTS.md — working in this repository

edge-compat is measured data plus the tools that produce and consume it. The
rules below keep the data honest; they are enforced by tests.

## What lives where

- `data/matrix/<backend>__<litert_version>.json` — op-level delegate
  compatibility, one snapshot per backend and runtime version. Entries carry
  `provenance` (`measured | vendor_doc | inferred | example`) and evidence.
- `data/sweep/<litertjs_version>/<date>/<model>.json` — browser sweep results
  (LiteRT.js, per backend). Append-only, dated.
- `data/device_runs/<runtime_version>/<date>/<model>__<device>.json` — device
  measurements. Append-only, dated.
- `cards/<model>/card.json` (source of truth) and `CARD.md` (rendered);
  `cards/index.json`, `cards/README.md`, `llms.txt` are generated by
  `edge-card index cards`.
- `schemas/` — the public JSON Schemas; `data/examples/` — example-provenance
  fixtures the tests run against.

## Commands

```sh
uv sync                      # Python >= 3.11
uv run pytest -q             # all tests, against example-provenance data
uv run ruff check .
uv run edge-lint <model.tflite> --matrix data/matrix/<snapshot>.json [--json|--md]
uv run edge-card index cards # regenerate index.json, cards/README.md, llms.txt
uv run edge-compat release-gate --site-dist site/dist
cd site && npm ci && npm test && npm run build   # the demo-zoo site (Node >= 22)
```

## Rules that tests enforce

1. Never fabricate a matrix entry, benchmark, device result or latency. Real
   data comes from measurements; fixtures are marked `"provenance": "example"`.
2. Never derive op-level matrix entries from model-level sweep results.
3. Generated files are regenerated, not hand-edited: `cards/README.md`,
   `cards/index.json`, `llms.txt`, `DELTA_LOG.md`, every `CARD.md`.
4. One snapshot file per (backend × runtime version); carry-forward downgrades
   `measured` to `inferred` with `evidence.derived_from` — never edit in place.
5. Exact TFLite builtin op names everywhere (`GATHER_ND`, `TRANSPOSE_CONV`).

The public repository is an export of a private lab repository (`EXPORT.md`);
open issues here, and pull requests against code, schemas or docs are welcome.
